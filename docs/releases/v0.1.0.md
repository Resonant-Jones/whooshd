# Whoosh'd v0.1.0

**Local-first inference broker for Apple Silicon and self-hosted AI workflows.**

First GA release.

---

## What It Is

Whoosh'd exposes an OpenAI-compatible chat and model surface while coordinating
local runtimes (MLX-LM Server, MLX-VLM, llama.cpp/GGUF, and a built-in stub).
It provides routing, readiness, model inventory, streaming, lifecycle
visibility, cancellation, overload behavior, a bounded control-plane error
contract, and a capacity control plane.

It does **not** replace lower-level inference engines. It is the small control
plane in front of them.

---

## What's New Since v0.1.0rc3

### Capacity control plane

- `CapacityController` decides how many requests may execute right now
- `fixed` mode by default — exactly `WHOOSHD_MAX_ACTIVE_REQUESTS`
- `adaptive` mode may only **lower** the effective active limit from a
  validated `CapacityProfile`; the operator ceiling is a hard bound
- Strict identity binding: a profile applies only to an exact match of model
  id, runtime, machine class, and host memory
- Conservative fallback to the operator ceiling on missing, invalid, or
  mismatched profiles
- `GET /runtime/capacity` for live visibility
- `python -m whooshd.bench.capacity_bench` for per-band calibration

### Request correlation

- Upstream `X-Request-ID` and Whoosh'd `X-Whoosh-Request-ID` kept distinct
- Preserved through queueing, batching, cancellation, and failure paths
- Cancellation by the Whoosh'd ID returns the correlation pair

### Control-plane v1 contract

- `whooshd.control.v1` version negotiation
- Structured error envelopes with stable codes and retryability
- Streaming failures after visible output never fabricate a successful
  `[DONE]`

### Runtime provenance and qualification

- Bounded `whooshd.runtime.v1` evidence on inventory and successful responses
- Target-scoped, additive `qualification_attestation`

### Authoritative model registry

- Operator-owned, fail-closed model allowlist
- Unknown and disabled model IDs do not fall through to adapter heuristics

### Logging safety

- Bounded Whoosh'd-owned log records under a documented safety contract
- Daemon ownership verification and log sanitization

## What Is Intentionally Not Included

- Production-ready continuous batching or token-step shared decode for MLX
  (Cave Thunder decision)
- Latency or throughput improvement claims beyond recorded validation packets
- Production ThreadWake KV reuse — backends report `unsupported` by default
- Durable KV snapshots (deferred)
- Embeddings, tool calling, multi-node routing, production auth hardening
- Model-independent capacity — profiles are bound to a model, runtime, and host

## Quick Start

```bash
git clone https://github.com/Resonant-Jones/whooshd.git
cd whooshd
pip install -e ".[dev]"

# Start the local daemon
whoosh -d
whoosh status

# Or run a foreground stub server
WHOOSHD_ADAPTER=stub python -m uvicorn whooshd.app:app --port 8000

# Sanity checks
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/runtime/capacity
sh scripts/smoke_stub.sh
sh scripts/smoke_openai_compat.sh
```
